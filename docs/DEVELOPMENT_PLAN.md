## 1. 项目定位与目标

### 1.1 一句话定位

**「心屿」是一个免费、私密、当下就能用的心理自助工具箱**——在用户情绪陷入低谷、无人可诉、也还不想求助专业帮助的间隙，提供经过循证方法整理的、分钟级可执行的自助练习。

### 1.2 目标人群

| 人群 | 场景 | 需求 |
|------|------|------|
| 普通成年人 | 偶发情绪崩溃、焦虑、失眠 | 即时安抚、当下缓解 |
| 学生/青少年 | 考试焦虑、人际关系压力 | 私密、不被打标签的自助 |
| 长期情绪困扰者 | 反复低落、长期失眠 | 结构化练习 + 就医引导 |
| 想改善心理状态的人 | 日常正念、自我觉察 | 可坚持的轻量练习 |

### 1.3 目标（SMART）

- 上线后提供 ≥10 个可执行的自助练习模块
- 每个模块遵循统一的"危机保护 → 方法 → 求助引导"结构
- 全站达到 WCAG AA 基本无障碍标准
- 危机热线提示出现在每个页面可见位置

## 2. 核心设计原则

1. **方法有据（Evidence-based）**：所有练习的逻辑根基来自认知行为疗法（CBT）、行为激活（BA）、正念减压（MBSR）、刺激控制疗法（失眠）等循证方法，而非心灵鸡汤。
2. **立刻可用（Actionable in minutes）**：用户在 60 秒内能开始第一步动作，而不是读完长篇大论。
3. **不评判（Non-judgmental）**：语气温和、克制、不说教，不用"你应该""你必须"。
4. **不诊断（No labeling）**：不写"你这是抑郁症/焦虑症"，只描述"可能的感受"。
5. **科学诚实（Intellectual honesty）**：明确边界——自助不等于治疗，复杂情况请就医。
6. **尊严优先（Dignity first）**：每个危机场景，把"求助"放在"自助"之前。

## 3. 伦理红线（最高优先级）

> 此章节为不可逾越的底线，任何功能开发均不得违反。

### 3.1 危机优先原则
- **任何页面顶部**必须有危机提示条：全国心理援助热线 12356、北京心理危机干预热线 400-161-9995。
- 当检测/提及"自伤、自杀"时，**必须先给出热线和就医路径，再谈自助内容**（顺序不可颠倒）。

### 3.2 免责声明闭环
- 全站页脚统一免责声明。
- 关于页（`about.html`）给出完整声明：内容不构成医疗建议，不替代诊断/治疗/用药。

### 3.3 不诊断、不打标签
- 文案禁用词：`确诊`、`你是XX症`、`你病了`、`你有心理问题`。
- 允许词：`你可能感到`、`常见的反应`、`这很正常`。

### 3.4 隐私
- 纯静态、无后端、无 cookie 追踪、无登录。用户所有状态仅存在本地浏览器（localStorage），不采集任何数据。

### 3.5 内容责任制
- 每个模块标注方法来源（如"本练习参考认知行为疗法 CBT"）。
- 留出错纠反馈入口，便于审校。

## 5. 模块详细规格

> 每个模块遵循统一模板：**危机条 → 当刻快速引导 → 步骤式练习 → 何时求助 → 来源说明 → 回首页**。

### M1 情绪急救 `emergency.html`（已上线，待深化）

**方法依据**：生理着陆 + 正念觉察；语气参照《也许你该找个人聊聊》的"被承接感"。

**现有内容**：①身体降温 ②落地呼吸 ③5-4-3-2-1 着陆法。

**深化方向**：
- [ ] 增加"一分钟万能启动"：无论多糟，先做"站起来 + 喝口水 + 开窗"三件套
- [ ] 增加"此刻我需要什么"的自检（冷/热/动/说——选一个能做的）
- [ ] 危机优先：顶部热线提示条升级为可点击、可复制

**验收**：用户从进入页面到开始第一步动作 ≤30 秒；无长段落拦路。

### M2 焦虑缓解 `anxiety.html`（已上线，待深化）

**方法依据**：《伯恩斯新情绪疗法》认知重评 + 呼吸法。

**现有内容**：①4-7-8 呼吸 ②肌肉放松 ③"担心想法 vs 现实"两栏。

**深化方向**：
- [ ] 引入伯恩斯"十种认知扭曲"清单（灾难化、非黑即白、过度概括等），帮助用户"命名"自己的思维陷阱
- [ ] 提供可下载/可打印的"想法记录表"（认知重评表）
- [ ] 增加"焦虑急性发作时"专用短流程（专治心慌、濒死感场景）

**验收**：用户能识别至少一种自己的常见认知扭曲并完成一次重评。

### M3 失眠助眠 `sleep.html`（已上线，待深化）

**方法依据**：刺激控制疗法（CBT-I 核心）+ 睡眠卫生（《睡眠革命》）。

**现有内容**：①固定起床时间 ②睡前后调 ③20分钟规则 ④身体扫描。

**深化方向**：
- [ ] 增加"睡眠卫生清单"（可勾选，本地保存）
- [ ] 加入"床=睡觉"的刺激控制说明图解
- [ ] 增加"躺下焦虑反刍"的应对：把待办写下来放在床外
- [ ] 明确区分：偶尔失眠 vs 长期失眠（≥1 个月）的就医指征

**验收**：用户能理解并应用 20 分钟规则；能判断自己是否该就医。

### M4 低落自救 `lowmood.html`（已上线，待深化）

**方法依据**：行为激活（BA）——行动先于感受（奥康纳《走出抑郁》）。

**现有内容**：①小步骤法 ②行动先于感觉 ③三件小事。

**深化方向**：
- [ ] 加入"价值方向"概念：找出低落时仍在乎的方向，据此设计小行动
- [ ] 提供"行动-心情"对应记录（完成动作后记录感受变化，强化正反馈）
- [ ] 增加"启动难"的兜底方案：连最小的动作都做不了时怎么办
- [ ] 明确"持续低落 ≥2 周"的就医提醒（不与单纯情绪低落混淆）

**验收**：用户能完成一次"选一小步 → 去做 → 记录感受"的闭环。

### M5 正念练习 `mindfulness.html`（已上线，待深化）

**方法依据**：正念减压 MBSR（一行禅师、卡巴金）。

**现有内容**：①三分钟呼吸空间 ②身体扫描 ③日常正念。

**深化方向**：
- [ ] 规范身体扫描流程（更细的指导语，约 8–10 分钟）
- [ ] 增加"走神是练习的一部分"的正念态度提示（避免自我苛责）

- [ ] 明确：正念是"保养"不是"急救药"，复杂情况仍需专业帮助

**验收**：正念态度正确传达（不评判走神）；练习可完整跟随执行。

---

### M7 想法记录 `thoughtlog.html`（新模块，强烈建议）

**方法依据**：伯恩斯认知疗法"想法记录表"——CBT 最核心的自助工具。

**页面结构**：
1. **教程**：什么是想法记录、为什么写
2. **互动表单（纯前端 JS）**：
   - 情境：发生了什么？
   - 自动想法：脑子里冒出了什么？
   - 情绪/程度：难过/焦虑 0–10
   - 认知扭曲：从十种清单里勾选（如灾难化）
   - 重评想法：更平衡的看法是什么？
   - 情绪再打分
3. **结果反馈**：本地保存，可对比前后情绪分

**技术**：简单 HTML 表单 + JS 状态管理（localStorage），无后端。
**验收**：用户完整完成一次"情境→想法→扭曲→重评→情绪变化"闭环。

### M8 自我关怀 `selfcare.html`（新模块）

**方法依据**：克里斯廷·内夫《自我关怀的力量》——自我友善、共通人性、正念。

**页面结构**：
- 什么是自我关怀（不是自我放纵）
- 三个组成部分讲解
- 练习：①对朋友说的话对自己说 ②手心温度安抚 ③自我关怀冥想文字版
- 常见误区澄清

**验收**：用户能完成一次向自己表达善意的话语练习。

---

### M9 关系修复 `relationship.html`（新模块）

**方法依据**：卢森堡《非暴力沟通》——观察、感受、需要、请求（四要素）。

**页面结构**：
- 冲突时大脑的"战斗/逃跑"机制（先冷静，别在情绪高峰沟通）
- 四要素拆解 + 例子（"当我看到…我感到…因为我需要…你能否…"）
- 区分"评价"与"观察"
- 何时该修复关系、何时该保护边界

**验收**：用户能把一句指责改写为一句非暴力表达。

---

### M10 意义感 `meaning.html`（新模块）

**方法依据**：弗兰克尔《活出生命的意义》意义疗法。

**页面结构**：
- 意义可以从哪里来：创造、体验、态度
- "为什么活着"的温和引导（不强行赋予答案）
- 低谷中寻找"此刻的意义"的小练习（为某个人/某件事/为明天的自己）
- 治坑提示：长期无意义感关联抑郁，建议专业帮助

**验收**：语气克制、不加压；提供至少一种具体的"当下意义"练习。

---

### M11 行动空间 `action.html`（新模块）

**方法依据**：行为激活进阶 + 目标拆解（奥康纳）。

**页面结构**：
- 大目标拆小（"写一页→写一段→写一行"）
- 每日三大行动清单（可勾选，本地保存）
- "行动-心情"追踪表
- 与 M4 低落自救配合，作为长期行动工具

**验收**：用户可创建一份当日最小行动清单并勾选完成。

## 6. 技术架构

### 6.1 纯静态方案（与现状一致）
```
D:/blog/blog/
├── index.html            首页（工具卡片网格）
├── *.html                各模块页面（M1–M11）
├── style.css             统一样式 + 主题
├── script.js             深色模式
├── data/
│   └── 可选：模块配置/想法记录扭曲清单等 JSON
└── .nojekyll             GitHub Pages 纯静态
```

### 6.2 本地交互（无后端的实现方式）
- **想法记录表（M7）**：原生 JS 表单 + `localStorage` 保存草稿与历史，纯前端完成"记录-重评-对比"。
- **行动清单（M11）**：本地 checkbox + `localStorage` 持久化。
- **呼吸引导（M5）**：现有 CSS 动画 `.breath-box` 扩展。
- **深色模式**：`script.js` 已实现。

> 所有数据仅存本地浏览器，符合隐私要求，无需服务器。

### 6.3 可靠性
- 相对路径，任何子路径部署可运行。
- 无第三方请求依赖（除 Google Fonts，可替换为系统字体以防加载失败）。
- 静态页面，天然抗故障。

## 7. 用户旅程与引导设计

### 7.1 三种典型旅程

**旅程 A：急性情绪（此刻很难受）**
```
进入 → 危机条(安全确认) → 情绪急救页 → 1分钟启动 → 呼吸/着陆 → 缓过来 → 可选记录
```

**旅程 B：想改善的困扰（焦虑/失眠/低落）**
```
进入 → 对应模块页 → 学方法 → 做练习 → 用工具(记录表/清单) → 长期改善 → 需时就医
```

**旅程 C：想求助但犹豫**
```
进入 → 求助资源页 → 常见顾虑科普 → 热线/就医分步指南 → 踏出第一步
```

### 7.2 首页引导优化
- 首页顶部：一句话定位 + 危机提示条
- 卡片区分"现在很难受"（情绪急救）与"想长期改善"
- 增加"从哪开始"的推荐路径（如：情绪急救→对应模块→正念保养）

## 8. 危机安全机制

> 这是本网站最核心的技术需求，优先级最高。

1. **全局危机条**：`index.html` + 所有模块页顶部固定可见，含可复制热线。
2. **危机优先排序**：涉及自伤/自杀的内容，先热线后自助。
3. **搜索内救急**：如未来增加站内搜索，需对自杀相关词优先呈现求助热线（可先不做，但规划时保留）。
4. **免责声明闭环**：页脚 + 关于页完整声明。
5. **求助链路**：每页结尾"何时该求助"引导至 `resources.html`。

## 10. 无障碍与可及性
